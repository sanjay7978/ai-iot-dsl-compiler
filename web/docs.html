01Quick start

You need a C++17 compiler, Python 3 and a C compiler (for Build & run). Node.js is optional, for running the JavaScript target.

1
Build the compiler
make
2
Start the web app
make run

Then open http://127.0.0.1:8000. Use make remote instead to let phones on the same Wi-Fi join.

3
Run the tests
make test

Runs the compiler checks, cross-target equivalence tests and the Python unit tests, then refreshes the numbers shown on the home page.

02The language

A program is a list of declarations followed by rules. Every sensor and device is declared once before it is used. Comments start with #.

smart_home.iot

        

        

          
ConstructFormNotes

          
            
SensorSENSOR name : NUMBERNumeric reading, such as a temperature or humidity.

            
SensorSENSOR name : STATEOne of ON OFF OPEN CLOSED TRUE FALSE.

            
DevicesDEVICE fan, light, acSomething the rules can switch or set to a level.

            
RuleIF cond THEN actionsActions are written one after another; no separator needed.

            
BranchesELSE IF cond THEN … ELSE …Any number of ELSE IF, at most one ELSE.

          
        

      


      

        
03Conditions & operators

        
Operators are listed from the loosest to the tightest binding. Parentheses override precedence.

        

          
LevelOperatorsWorks on

          
            
1ORtrue/false

            
2ANDtrue/false

            
3NOTtrue/false

            
4> < >= <= == !=NUMBER with NUMBER; STATE only with == and !=

            
5+ −NUMBER

            
6* / and unary −NUMBER

          
        

        
Rule analysis. After type checking, each condition is put into disjunctive normal form and checked with interval and state-set reasoning. The compiler warns about conditions that can never be true or are always true, ELSE IF branches that can never run, and two rules that set the same device differently for the same inputs, and it gives example inputs.

05Grammar & LL(1)

        
The grammar is stored as data inside the compiler (src/grammar.cpp). The compiler computes the FIRST and FOLLOW sets and fills the LL(1) parse table. If any cell had two productions, the grammar would not be LL(1). Each nonterminal is one function of the recursive-descent parser.

06Compiler phases

        
    
          
  1. Lexical analysisA hand-written scanner (a DFA with longest match) turns characters into tokens and reports bad characters with fixes.
    2. 
          
  2. Syntax analysisRecursive descent over the LL(1) grammar; panic-mode recovery reports several errors in one run.
    3. 
          
  3. Abstract syntax treeOne expression tree with correct precedence, plus rules, branches and actions.
    4. 
          
  4. Semantic analysisSymbol table, types (NUMBER, STATE, BOOL), argument checks, did-you-mean suggestions and rule analysis.
    5. 
          
  5. Intermediate codeThree-address code with temporaries, labels and source spans for every instruction.
    6. 
          
  6. OptimizationBasic blocks and a CFG; liveness and available-expressions dataflow; eight passes repeated until nothing changes.
    7. 
          
  7. Code generationOne structured emitter with four target back ends; if/else structure is recovered from the IR.

Messages produced by the compiler for the bundled error examples. Where a fix is listed, the Studio shows it as a one-click button.

lexicalunexpected '=': assignment is not supported, did you mean '=='?Replace '=' with '=='

            
syntaxexpected 'IF', 'SENSOR' or 'DEVICE' at the start of a statement but found 'if' (keywords are uppercase, did you mean 'IF'?)Change to 'IF'

09AI setup

        
All options are free. Copy .env.example to .env and fill in what you want. With nothing set, a local Ollama model is used if Ollama is running; otherwise the built-in offline converter handles common sentence patterns.

        
.env


# auto (default), groq, gemini, ollama, offline
AI_PROVIDER=auto
GROQ_API_KEY=            # https://console.groq.com/keys
GEMINI_API_KEY=          # https://aistudio.google.com/apikey
OLLAMA_MODEL=            # e.g. qwen3, after `ollama pull qwen3`

        
Every answer is checked. The model's DSL is compiled by iotc. If it has errors, the compiler's messages are sent back for one repair attempt, and the Studio shows whether the final answer is verified. An AI fix in the Problems tab is offered only when the error it targets is gone and no new errors appear.

10Phone remote

        
Start the server with make remote. Then click Phone in the Studio and scan the QR code with a phone on the same Wi-Fi. The phone shows the program's sensors; moving them updates the digital twin on the laptop through server-sent events.

        
Security. Requests from other devices can reach only the remote page and its two endpoints, and they need the random session key in the QR code. Compiling, running code and the AI stay available only on the laptop itself.
